# 01 — 文章可上傳/顯示超過 3 張圖片

**What to build:** 使用者發文或編輯文章時，可以附上超過 3 張圖片（上限 99 張、單次總大小上限 30MB），不再受限於固定 3 個格子。文章詳情頁以縮圖網格呈現該篇文章的全部圖片，點擊任一張可開燈箱放大瀏覽。

**Blocked by:** None — can start immediately

**Status:** ready-for-agent

- [ ] 使用者發文時可以透過「新增圖片」持續加入圖片（不限於 3 個固定格子），也可以個別移除已選的圖片
- [ ] 單篇文章最多可附 99 張圖片，超過時前端擋下並提示明確錯誤，不送出請求
- [ ] 一次送出的圖片總大小超過 30MB 時，送出前就被擋下並提示明確錯誤，不會呼叫發文/編輯的伺服器端請求
- [ ] 文章的圖片資料改成以單一個「圖片清單」欄位儲存（JSON 陣列字串），空清單有固定的標準表示法，讀取端一律用同一種方式解析
- [ ] 圖片驗證/組裝邏輯維持是一個獨立、可被 Node 測試覆蓋的純函式，對任意長度的圖片清單套用既有規則：新圖片直接接受；字串必須完全等於這篇文章既有圖片清單裡的某個值，否則整個請求視為異常、整個拒絕（不悄悄當成空白處理）
- [ ] 即使前端沒有擋住超過 99 張，伺服器端的驗證邏輯本身也要有防禦性上限檢查並拒絕
- [ ] 圖片清單裡的每一個網址在寫入前，都套用既有的公式注入跳脫處理
- [ ] 文章列表批次讀取（進板時一次讀取整批文章）維持同一次 range read 讀完，不因為欄位結構改變而增加 Sheets 讀取次數
- [ ] 文章詳情頁以縮圖網格呈現該篇文章的全部圖片（不限 3 張），點擊任一縮圖可開燈箱放大瀏覽
- [ ] 新增的燈箱渲染程式碼透過事件監聽器綁定點擊事件，不使用內嵌的 onclick 屬性字串插值
- [ ] 既有圖片驗證邏輯的 Node 測試更新為涵蓋任意長度陣列：超過 3 個元素、陣列中間有被跳過的空值、超過 99 張時的防禦性拒絕、出現不合法字串時整個請求被拒絕
- [ ] 既有涉及舊圖片欄位斷言的測試，改成對新的圖片清單欄位斷言
