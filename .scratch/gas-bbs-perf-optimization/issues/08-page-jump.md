# 08 — 跳頁功能(直接跳到指定分頁)

**What to build:** 在「載入更早的文章」之外,額外提供跳頁機制:文章列表上方顯示目前頁次/共幾頁的指示器,點擊可以直接輸入頁碼跳過去,也提供◀/▶箭頭與「回到最新」/「跳到最早」快捷按鈕。這是使用者提供參考實作(`bbschangepage.zip`)、經評估符合 BBS 平台慣例後採納並優化整合進專案的功能,不是原本 7 張 ticket 規劃的一部分,故編號承接為 08。

**Blocked by:** 05 — 看板批量預載端點與前端串接(單頁)、06 — 分頁與「載入更早的文章」

**Status:** done

- [x] `boardBulk.js` 的 `getBoardBulkPage` 額外回傳 `totalCount`(該看板文章總數)與 `pageSize`(這次實際用的批次上限),不需要多一次讀取或多一次排序——讀表跟排序本來就要做一次,順手把已經算好的 `allArticles.length` 帶出去
- [x] 前端文章列表上方新增 pager bar:`hasMore` 或已經跳過頁時顯示,總頁數 ≤ 1 的看板完全不出現,使用者感覺不到差異
- [x] 頁碼指示器可點擊,開啟跳頁彈窗,可直接輸入頁碼(自動 clamp 在 1~總頁數範圍內)、或點「回到最新」/「跳到最早」快捷按鈕
- [x] ◀/▶箭頭以目前已載入範圍的邊界為準各跳一頁
- [x] **比參考實作多做的優化**:跳頁目標如果剛好已經在目前累積載入的連續範圍內(例如按過幾次「載入更早的文章」),直接從本地資料收斂渲染,不呼叫伺服器——沿用這輪一路以來「少次量多」的原則,不是每次跳頁都重新打一次 `getBoardBulkFromToken`
- [x] **比參考實作多做的修正**:輸入 `0` 時原本會被當成無效輸入直接忽略,改成正確 clamp 到第 1 頁
- [x] `boardBulkCache` 新增 `baseIndex` 欄位,記錄 `pages[0]` 對應到後端真正的第幾頁;「載入更早的文章」改成從 `baseIndex + pages.length` 繼續往後累加,兩種操作方式(累加載入、跳頁)並存不衝突
- [x] 本人發文的樂觀本地插入(`patchArticleListOnCreate`)在 `baseIndex !== 0`(使用者正停在跳頁後的某個舊頁次)時改為退回完整重新載入,不會把新文章插進錯誤的頁次
- [x] `loadArticles`(進板/切板)的版本比對只在 `baseIndex === 0` 時才拿本地版本值去比對,`baseIndex` 不是 0 時視為需要重新讀取——這代表使用者切到別的看板再切回來,一律回到最新一頁,不會保留切走前跳到的舊頁次(已知取捨,跟大多數論壇「重新進入看板一律看最新」的習慣一致)
- [x] **實作時發現、順手修正的既有問題(比這次跳頁功能範圍更早就存在)**:發表文章、編輯文章、發表回覆、刪除回覆這四個寫入端點,原本無論文章實際在哪一頁,一律只 bump 第 0 頁的版本 key(ticket 05 當時已知、標記給「未來再考慮」但沒真的處理的限制)。跳頁功能上線後,使用者更容易直接停留在很舊的頁次編輯/回覆,這個缺口更容易被踩到。新增 `boardBulk.js` 的 `findArticlePageIndex`(給定 articleId,回傳它目前排序下落在哪一頁),四個寫入端點改用它找出正確頁次再 bump 對應版本,而不是寫死 `:page0`。新發表文章維持寫死 `:page0` 不變(新文章一律 `createdAt` 最新,必定落在第 0 頁,不需要現查)。刪除文章的已知簡化:只 bump 被刪文章本來所在的那一頁,沒有連帶 bump 更舊頁次因為位移而跟著改變邊界的部分(機率低、影響小,頂多看到頁碼邊界有一格誤差,不會顯示錯誤或不存在的內容)
