# 06 — 分頁與「載入更早的文章」

**What to build:** 看板文章數超過批次上限時,文章列表最下方出現「載入更早的文章」按鈕;使用者點擊後,系統整批載入下一批更舊的文章(含內文與回覆),累加進已經載入的資料,不會重新讀取已經載入過的部分。使用者可以持續點擊,逐批把更舊的文章載入,直到沒有更多為止(按鈕消失)。

**Blocked by:** 05 — 看板批量預載端點與前端串接(單頁)

**Status:** ready-for-agent

- [x] 進入看板取得第一批資料時,`hasMore` 為 true 的情況下,文章列表最下方顯示「載入更早的文章」按鈕——`renderArticleListFromCache` 在文章清單後面,`entry.hasMore` 為 true 時才 append 這顆按鈕
- [x] 點擊按鈕後,前端以下一個頁次呼叫 Ticket 05 的批量端點,取得下一批文章與回覆——`loadMoreArticles` 用 `entry.pages.length` 當下一頁的 `pageIndex`
- [x] 新載入的一批附加(append)進既有的記憶體快取結構,不覆蓋、不重複已經載入的頁次——`entry.pages.push(...)`,不重新指派整個 `pages` 陣列
- [x] 已經載入過的頁次,再次點擊按鈕不會被重新整批讀取——只會去載入還沒載入過的下一頁——`nextPageIndex` 永遠是目前已載入頁數,不會重複要求同一頁;沒有已知版本值可帶(這頁本來就沒讀過),伺服器一定整批回傳,行為正確
- [x] 新載入這批文章底下的任一篇文章、任一則回覆,點開後一樣直接從記憶體快取渲染,不呼叫伺服器——`findCachedArticleLocation_`(ticket 05 已完成)本來就會跨所有 `pages` 找,不需要額外改動
- [x] 持續載入直到 `hasMore` 為 false 時,「載入更早的文章」按鈕消失——`entry.hasMore = !!res.hasMore` 更新後重新 render,`hasMore` 為 false 時該按鈕的 append 條件不成立
- [x] 看板文章數沒有超過批次上限的情況下(第一批的 `hasMore` 就是 false),完全不出現「載入更早的文章」按鈕,使用者感覺不到任何差異
- [x] 使用者離開看板又切回來時,如果版本沒變,前端沿用記憶體裡目前已經載入的所有頁次(不會因為切出去又切回來就把已經多載入的舊頁次清掉、退回只有第一頁)——確認 `loadArticles` 的 `res.unchanged` 分支本來就是提早 return、完全不碰 `boardBulkCache[boardId]`,這是 Ticket 05 就已經正確的行為,這張不需要額外修改
  - **已知的小限制(不在這張驗收範圍內,順便記錄)**:上述只涵蓋「第 0 頁版本沒變」的情況;如果版本**有變**(例如板上有人發了新文章),`loadArticles` 會用新的第 0 頁整個覆蓋掉 `boardBulkCache[boardId]`,連帶把使用者先前已經點「載入更早的文章」多載入的第 1、2...頁一起清掉,退回只剩第 0 頁(需要重新點「載入更早的文章」才能拿回來)。不是資料錯誤(不會顯示錯的內容),只是要多點幾次——這張 ticket 的文字沒有要求處理這個情境,先如實記錄,之後如果覺得有感再開新 ticket 處理
